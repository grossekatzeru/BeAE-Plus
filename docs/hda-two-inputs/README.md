# Запись с двух входов звуковой карты одновременно (BeAE-Plus + Haiku hda)

Отчёт о проделанной работе и инструкция по воспроизведению на другом компьютере.
Всё собрано и проверено только на одной машине (см. «Оборудование»). Патчи Haiku
**не являются универсальными**, см. «Ограничения».

## 1. Задача

1. Выбирать вход системной карты (Mic in / Front Mic in / Line in) прямо в BeAE.
2. Писать два входа карты одновременно в две дорожки.
3. Убрать устаревший источник «External (connect in Cortex)».

## 2. Оборудование и версия

- Codec Realtek ALC1220 (10ec:1220), контроллер Intel 8086:a2f0 (200 Series PCH HD Audio), плата ASRock (subsystem 1849:1220).
- Входные конвертеры (АЦП): виджеты 8 и 9; селекторы 35 (ADC8) и 34 (ADC9); входные пины 24 (Mic in), 25 (Front Mic in), 26 (Line in).
- Haiku из исходников (`/boot/home/soundrecorder/haiku`), драйвер `src/add-ons/kernel/drivers/audio/hda`.

## 3. Что выяснили

1. Штатный драйвер `hda` открывает **один** поток записи с **одним** АЦП (первая группа, мультиплексор «Input» id 140). Узел `HD Audio` в Media Kit поэтому имеет один выход, а второй АЦП (мультиплексор id 154, mute 151, gain 152) в поток не входит. Системная «Звукозапись» и BeAE пишут только первый АЦП.
2. Выбор входа делается параметром `B_INPUT_MUX` («Input») через `BDiscreteParameter::SetValue()`, а не через `BMediaRoster::SetParameterData`. В списке мультиплексора есть и выходные пины (дают шум), поэтому BeAE показывает только Mic/Line-имена.
3. Состояние mute (параметры 137 и 151) Haiku восстанавливает после загрузки. Если у второго АЦП стоит «Выключить звук», вторая дорожка пишет ровный шум.
4. Баг в `multi_audio` (`MultiAudioNode.cpp`): размер буфера каждого выхода считается по **всем** входным каналам, а не по каналам этого выхода. С двумя стереовыходами буфер вдвое больше данных, вторая половина — нули, `size_used` = полный размер. Симптом: пульсирующий звук (пачки данных и паузы).
5. Попытка исправить размер буфера при подключении (BeAE) даёт «Bad media format»: roster отклоняет формат с buffer_size, отличным от объявленного. Поэтому в BeAE сделана обрезка нулевого хвоста при приёме, а настоящее исправление — патч add-on.

## 4. Что изменено

### 4.1 Драйвер hda (`hda-2adc.patch`, применять из каталога `src/add-ons/kernel/drivers/audio/`, `patch -p1`)

- `driver.h`: `#define HDA_MAX_RECORD_CONVERTERS 2`.
- `hda_codec.cpp`:
  - `hda_widget_find_input_path`: для пина проверяется только `WIDGET_FLAG_OUTPUT_PATH` (входные пины могут быть общими для двух путей);
  - `hda_audio_group_get_widgets`: у записи не больше `HDA_MAX_RECORD_CONVERTERS` конвертеров, но цикл идёт по **всем** виджетам, потому что именно в нём включаются пины и снимается mute усилителей (первая версия обрывала цикл раньше и давала шум даже в штатной «Звукозаписи»).
- `hda_controller.cpp`: у каждого следующего конвертера записи канал потока увеличивается на 2 (`stream id<<4 | channel`).
- `hda_multi_audio.cpp`: каналов записи `2 * num_io_widgets`, таблица каналов строится динамически (выходы, входы, 2 выходные и 2 входные шины, стерео L/R).
- В итоге формат потока записи 4-канальный (F=0x1833), в syslog `num channels 4`, в Cortex у узла два выхода `in0` и `in1`.

### 4.2 Add-on multi_audio (`multi_audio-buffer.patch`, из каталога `src/add-ons/media/media-add-ons/`, `patch -p1`)

Новые `_OutputBufferSize()` и `_UpdateOutputBufferSize()`: размер буфера = `return_record_buffer_size * sampleSize * channel_count` самого выхода. Применяется после создания выходов, в `_SetNodeInputFrameRate` и в запросе смены формата. **Не проверено на Haiku** и не компилировалось.

### 4.3 BeAE-Plus (коммиты в main)

| Коммит | Что |
|---|---|
| 20dd1a8 | дамп параметров системного входа в `~/BeAE_input_params.txt` (диагностика) |
| cc79f22 | меню источника дорожки: Mic in / Front Mic in / Line in |
| e6d11ed | меняется только первый мультиплексор |
| 7a452b3 | второй АЦП на другой дорожке (второй выход узла) |
| 5f7a2a3 | дамп после выбора входов, до 6 раз |
| b929b2b | исправление буфера при подключении — **заменено**, давало «Bad media format» |
| 12c53fd | обрезка буфера multi_audio до реальных данных при приёме |
| d44d5d6 | удалён источник «External» |
| f241cb8 | обрезка только пока хвост нулевой (работает и с исправленным add-on) |

В меню: «Системный вход» с вложенными пинами (`Prefs.rec_input_pin`) и пункты «2: <пин>» (`Prefs.rec_input_pin2`, второй выход узла, второй мультиплексор). Старое значение `@external` читается как системный вход.

## 5. Как воспроизвести на другом компьютере

### 5.1 Проверить, нужна ли вообще правка драйвера

1. В Cortex у узла «HD Audio» смотрите число выходов. Если выход один, а в настройках «Медиа» видно два мультиплексора «Input», картина та же.
2. Снимите лог: `listdev`, `syslog | grep hda`. Нужны id виджетов АЦП, селекторов и входных пинов вашего кодека.
3. Патч написан под ALC1220 с двумя АЦП в двух независимых группах. На другом кодеке `HDA_MAX_RECORD_CONVERTERS` и нумерацию каналов надо проверять.

### 5.2 Сборка Haiku-части

```
cd /boot/home/soundrecorder/haiku        # дерево Haiku, рядом ../buildtools
cp -r src/add-ons/kernel/drivers/audio/hda ~/hda_original   # резервная копия
cd src/add-ons/kernel/drivers/audio
patch -p1 < <путь>/hda-2adc.patch
cd ../../../../../src/add-ons/media/media-add-ons
patch -p1 < <путь>/multi_audio-buffer.patch    # по желанию
cd /boot/home/soundrecorder/haiku
mkdir -p generated.x86_64 && cd generated.x86_64
../configure -j4 --cross-tools-source ../../buildtools --build-cross-tools x86_64   # один раз
jam -q hda                      # драйвер
jam -q hmulti_audio.media_addon # add-on (если патчили)
```

Замечание: jam сравнивает mtime. Файлы из zip со старой датой не пересобираются, делайте `touch` изменённых файлов перед `jam`.

### 5.3 Установка (без перезаписи системных файлов)

```
mkdir -p ~/config/non-packaged/add-ons/kernel/drivers/dev/audio/hmulti
cp generated.x86_64/objects/haiku/x86_64/release/add-ons/kernel/drivers/audio/hda/hda \
   ~/config/non-packaged/add-ons/kernel/drivers/dev/audio/hmulti/
```

Путь к собранному файлу может отличаться (`find generated.x86_64 -name hda -type f`). Затем перезагрузка. Копия из non-packaged перекрывает системную.

Откат: удалить этот файл и перезагрузиться (если система не поднимается, загрузка в безопасном режиме с зажатым Shift).

Add-on: `hmulti_audio.media_addon` кладётся в `~/config/non-packaged/add-ons/media/`. Риск: может загрузиться и системная копия, тогда узлы задублируются. Это не проверялось.

### 5.4 Проверка

1. `syslog | grep hda` — `num channels 4`.
2. Cortex: у «HD Audio» два выхода `in0`, `in1`.
3. «Медиа» → вход: у обоих АЦП снят флажок «Выключить звук» (параметры 137 и 151); Haiku сохраняет его после загрузки.
4. BeAE: на дорожке 1 источник «Системный вход» → нужный пин, на дорожке 2 пункт «2: <другой пин>». Включить запись на обеих и записать. Звук должен идти раздельно, без пульсации.
5. Диагностика: `~/BeAE_input_params.txt` и строки `BeAE:` в выводе (`card input ... -> parameter ...`, `multi_audio buffers hold ... of ... channels`).

## 6. Ограничения и открытые вопросы

- Патч драйвера проверен только на ASRock + ALC1220 и на одной ревизии Haiku. На других картах запись с двумя АЦП становится 4-канальной, что для приложений, ожидающих стерео, может быть неожиданно. Для апстрима это следовало бы сделать опцией в `hda.settings`.
- Патч multi_audio не проверен на Haiku.
- BeAE не снимает mute выбранного входа сам (идея на ~1 ч, не сделана).
- Сообщение `resolve symbol "_ZN3flpC1E..."` при старте BeAE вызвано устаревшим VST2-плагином в папках vstplugins, к этой работе не относится.
- Всё это не собиралось и не тестировалось автоматически; проверялось вручную пользователем на Haiku.
