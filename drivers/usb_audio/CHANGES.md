# usb_audio: изменения этапа 1 (относительно исходников Haiku)

Не компилировалось и не тестировалось на Haiku (только проверка синтаксиса).

## Stream.cpp / Stream.h
- Частота дискретизации инициализируется при старте (48000, иначе 44100, иначе максимальная). Раньше `fSamplingRate` оставалась 0, буферы создавались только при смене формата приложением.
- Запись: пакеты принимаются в отдельную raw-область (`request_length` = максимальный пакет endpoint), в буфер приложения копируются только реальные данные (`actual_length`), пакеты с ошибкой пропускаются. Раньше пакеты разной длины (44/45 кадров на 44.1 кГц) оставляли дыры и обрезались, это давало треск.
- Воспроизведение: кадры распределяются по пакетам равномерно (44,44,...,45), буфер строится на целое число периодов. Раньше всегда floor, устройство недокармливалось.
- Области памяти с B_FULL_LOCK (в них пишет USB callback), `delete[]` для массива дескрипторов, `_FreeBuffers()`.
- `SetGlobalFormat`: частота проверяется по дескриптору, `SET_CUR` отправляется только если у endpoint есть Sampling Frequency Control или у потока несколько частот, при отказе устройства состояние откатывается; в структуру возвращается реальный формат.
- `SET_CUR` частоты отправляется и при `OnSetConfiguration`.
- `Start()`: `fIsRunning` выставляется до постановки передач в очередь (гонка с callback), ошибка постановки отменяет запуск.
- `GetBuffers`: каналы второго потока того же направления пишутся со смещением `startChannel` (раньше цикл не выполнялся, в user space копировался неинициализированный стек ядра, и дескрипторы затирали бы первый поток), число каналов ограничено запросом приложения.

## Device.cpp / Driver.cpp
- Проверка `new Stream` на NULL, при повторном подключении старые потоки удаляются (раньше дублировались).
- Лимиты на размеры из user space (`request_*_buffers`, `item_count`) для массивов на стеке ядра.
- `usb_audio_open` находит устройство по номеру в имени (раньше перебор останавливался на первой пустой ячейке).

## Не сделано (следующие этапы)
- UAC 2.0 (драйвер отбрасывает заголовок с bcdADC != 0x0100).
- Более 2 каналов, 24 бита в 3 байтах, микрокадры High-Speed, feedback endpoint.
- Воспроизведение: логика `fCurrentBuffer` и повторной постановки в очередь при старте сомнительна, оставлена как была.
